# Tag-state and sample-packing optimization

The verified Lean optimizer now indexes per-wire tags with an array and packs
each sampled tag once per pass. The final comparison improves all six completed
workloads, with identical emitted QASM and preserved correctness proofs. Large
QFT remains limited by Hadamard cancellation.

## Results

Times are whole native CLI process durations, including startup, parsing,
optimization, checked serialization, output writing, and exit. Each row uses one
warmup per binary and six measured baseline/candidate pairs in AB/BA order. Both
commands are pinned to logical CPU 2, a fast physical core, on an AMD Ryzen AI 9
HX 370. Compilation is excluded. `-O3` uses the same warm synthesis-table cache.

| Circuit | Level | Baseline median | Candidate median | Speedup |
| --- | --- | ---: | ---: | ---: |
| `gf2^16_mult` | O1 | 0.138 s | 0.081 s | 1.71× |
| `gf2^32_mult` | O1 | 0.833 s | 0.328 s | 2.54× |
| `gf2^64_mult` | O1 | 8.431 s | 2.018 s | 4.18× |
| `hwb8` | O1 | 0.419 s | 0.183 s | 2.29× |
| `chebyshev` | O1 | 10.862 s | 2.060 s | 5.27× |
| `gf2^32_mult` | O3 | 1.288 s | 0.760 s | 1.70× |

Every measured pair was faster with the final candidate. These are noisy timing
measurements on a shared machine with dynamic CPU frequencies. The small
multiplier's candidate median is below 100 ms, where startup and timing noise
matter more. The raw distributions and paired deltas are retained; the speedup
is the ratio of the two medians, not an aggregate across unrelated circuits.

The 309,835-gate `qft20` scalability case exceeded a 60-second limit on both the
baseline and final candidate. It has no completed-run speedup claim. The
baseline suite was unpinned; the final QFT profile was pinned to CPU 2.

## Attribution and implementation

The baseline `gf64 -O1` profile assigned 13.09% of self samples to list indexing
and 11.20% to list updates, alongside substantial allocation and deallocation.
Generated C showed `TState.tagOf` calling the list getter and `TState.step`
rebuilding list prefixes. The new `Array Tag` representation uses indexed reads
and `setIfInBounds`, retaining zero reads and ignored writes outside the state.
The simulation proof now relates the array's size and entries to the symbolic
list of parities.

Generated C releases the old state reference before `lean_array_fset`, so an
exclusive array can be updated in place. Shared snapshots can still require a
copy. List indexing and list-update helpers no longer appear among the final
`gf64` profile's samples.

The array-only candidate exposed the next representative cost in Cobble:
repeated conversion of sampled bit functions into packed numbers. Its profile
included 6.72% in `__gmpz_n_pow_ui`, plus substantial multiprecision allocation.
`wordsOf` reconstructed all 128 bits every time a merge scan requested a draw.

`sampleWords` now packs the finite sample into an array once. The compiled
`phaseFoldWithSampleCached` calls it before constructing the draw closure; the
closure only checks the index and reads an array element. The theorem
`sampleWords_eq` establishes the exact same stream, including zero padding.
The compiler applies the proved equality
`@phaseFoldWithSample = @phaseFoldWithSampleCached` via `csimp`. The ideal
randomized model still uses the original definition and sample distribution.

The fresh Cobble profile completes in about 2 seconds; exponentiation is down
to 2.49% of a much smaller sample total. Cancellation scans now account for a
larger share. Attribution profiles use `perf 6.19.10`, event `cycles:u`, at
997 Hz. Early DWARF call chains contained invalid callers, so inclusive stacks
were discarded. Attribution uses sampled instruction pointers, isolated pass
profiling, and generated C. Early profiles were unpinned; final profiles use
CPU 2. Headline timings above come from separate runs without a profiler.

## Correctness and identity

- `lake build` passed after both changes, rebuilding affected proof and test
  modules in batch. Beam was used for speculative proof checks and diagnostics;
  no server checkpoints replaced batch compilation.
- A new regression guard exercises the sampled entry point with tags differing
  only in bit 127, ensuring the cache does not truncate high bits or merge an
  unrelated rotation.
- All 84 comparison invocations exited successfully: 72 measured runs and 12
  warmups. Gate, two-qubit, T-count and depth reports were identical across every
  invocation of each case. The retained baseline/candidate output files are
  byte-for-byte identical for all six cases.
- Executable, source, input and toolchain identities remained stable during
  every comparison. The current built executable matches the measured candidate.
- The standalone benchmark runner was exercised on real circuits, including
  its timeout path, and smoke-tested again after its final metadata update.

Baseline source: clean commit `2c29be4` (full revision in `context.json`).
Toolchain: `leanprover/lean4:v4.33.1`, pinned mathlib revision
`0df444a360eaa60ab8c11dca51a86af692955474`, Lake's normal release flags.

deterministic code-size observations, separate from timing and sample noise.

The one-time default table build took 24.446 seconds and produced 549,457 table
entries. It is recorded separately and excluded from the warm comparison.

## Experiment history and evidence

The array-only trial improved arithmetic but showed an unresolved 6% slower
Cobble median in unpinned runs. This machine has cores with different maximum
frequencies. That trial was not accepted as the final change: representative
profiling led to sample caching, and the complete final surface was rerun on one
fixed core. The original trial and distributions remain available.

Local, git-ignored evidence is under `experiments/lean-runtime-20260910/`:

- [Final timings and paired deltas](../../experiments/lean-runtime-20260910/final-summary.json)
- [Validation and source hashes](../../experiments/lean-runtime-20260910/validation.json)
- [Initial checkout and machine context](../../experiments/lean-runtime-20260910/context.json)
- [Native sizes and symbols](../../experiments/lean-runtime-20260910/native-size.json)
- `final-<case>/manifest.json`, `runs.jsonl`, `identity-check.json`,
  `git-tracked.patch`, and stdout/stderr retain exact command arrays, identities,
  execution order, timings and endpoints.
- `compare-<case>/` and `comparison-summary.json` retain the array-only trial.
- `*.perf.data`, `*-self.txt`, generated C snapshots, binaries and build logs
  retain profiling and compilation evidence.
- `compare-final.py` records the exact invocation of the profiling skill's
  comparison helper. The reusable suite is documented in [README.md](README.md).

Decision: accept the array state and proved sample cache together. All completed
representative workloads improve, output and proof checks pass, and fresh
profiles confirm the predicted cost reductions.

Next measured target: QFT cancellation. In the final 60-second prefix profile,
`scanH` accounts for 50.66% of self samples, `Gate.support` for 14.21%, and
`reduceStep` for 8.82%. This is a separate scan/rewrite bottleneck; the command
does not reach its output endpoint within the current benchmark limit.
