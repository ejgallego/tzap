Six implementation commits made the Lean CLI 1.7–10.4× faster on completed original-baseline cases. QFT now finishes in 2.14 seconds, while the original executable reaches the 60-second limit. Rust remains 16–121× faster. The fresh final comparison validates identical outputs; each earlier experiment retains its own control and decision.

This report reuses the 2026-09-10 evidence. It runs no benchmarks. Start with the baseline and directly measured totals, then inspect individual improvements and rejected ownership experiments. Timings and samples are noisy; hashes, generated code and proof contracts provide different kinds of evidence.

Phase attribution and profiles

A full application boundary

All headline observations include process startup, parsing, optimization, normal reporting, serialization, output writing and exit. Lean also reparses its output to check the round trip. Rust is explicitly sequential. O3 synthesis caches are already populated, but loading them is inside the measured command. Fresh 128-bit tags come from OS entropy. These are application timings, not a controlled comparison of language overhead.

We have not measured a complete phase-duration breakdown. Self-profile symbols identify costs to investigate; they do not justify assigning seconds to startup, parsing, optimization or shutdown.

From asymptotic scans to preparation placement

Array tags removed repeated list indexing and prefix reconstruction. Caching finite samples removed repeated packing. Hadamard sweeps removed whole-list restarts after each successful rewrite. Finally, keeping sampled entropy packed removed an unnecessary word/bit/word round trip. Each source change has its corresponding invariant or equivalence proof. The rejected eta-expanded helper illustrates why generated C, rather than source placement alone, mattered.

Linearity was a mechanism question, not a promised speedup

The tag-state mutator already exposed an exclusive array update after releasing its parent. Unconditional composition removed another owner. Releasing gate wrappers and retaining only a count in fixpoint iteration also changed ownership as intended, but did not improve the representative results. Those candidates were rejected. The accepted fixpoint loop removes eager pass construction while preserving the prior ownership during the length comparison.

The earlier always-sweep Hadamard candidate and eta-expanded sample helper are documented as rejected designs in the archived reports and patches; they are not mixed into accepted distributions.

What the profiles can support

Early DWARF chains had impossible callers, so inclusive flamegraphs were discarded. The bundled viewers display self instruction-pointer weights from the intended native executables. They are instrumented runs separate from the acceptance timing distributions. The old QFT profile is a 60-second prefix; the later profiles complete the CLI, so their phase mixes differ. No synthetic chronology or Perfetto timeline is presented.

After the accepted changes, allocation, list scans and O3 table loading remain useful targets to attribute. A small array-copy percentage does not prove that all ownership costs are negligible.

Correctness and identity

The final branch passed a batch Lake build, including affected proof modules and regression guards. Beam was used for speculative checks without replacing those builds with saved server checkpoints. The final suite has 162 invocations: 161 successes and the single original QFT timeout. All successful output files match within their workload and independent scans reproduce gate counts, two-qubit counts, T-counts and depth. Earlier campaigns validate each run’s reported metrics and the final retained QASM pair; their runners reused output paths, so they do not preserve a distinct QASM file for every historical run.
